## Your task

現在の差分を確認し、**あなたの判断で**意味的にコミット分割して commit & push まで完走する。
分割案の承認は取らない（事後報告でよい）。途中で止まってよいのは秘匿情報の項に該当するときだけ。

1. `git status` と `git diff` で全変更（未追跡ファイル含む）を把握する
2. **秘匿情報スキャン**（下記）— コミット対象に秘匿情報がないか必ず確認する
3. **意味的に分割して順次 commit** — 1コミット＝1つの目的（機能追加 / リファクタ / ドキュメント /
   運用方針の変更 / データ更新 は別コミット）。目的ごとに `git add <path>` でステージング。
   分割不要な単一目的の差分なら1コミットでよい。
4. `git push`（リモートが先行して reject されたら `git pull --rebase` してから再 push）
5. 最後に「何をどう分けたか」「除外したものがあれば何故か」を簡潔に報告する

### 秘匿情報スキャン（コミット前に必須）

- 差分と未追跡ファイルの中身を確認し、秘匿情報を探す。例:
  API key / アクセストークン（`ghp_` `gho_` `sk-` `xox` `AKIA` など）、パスワード、
  `-----BEGIN ... PRIVATE KEY-----`、`client_secret`、`.env` 系ファイル、認証情報入りの設定ファイル。
- **ファイルごと秘匿物**（`.env`、credentials.json 等）→ `.gitignore` に追記してコミットから除外し、
  残りの安全な変更だけで commit & push を続行。除外した旨を報告する。
- **必要なファイルの中に秘匿値が埋め込まれている**（ソースコードにハードコードされた key 等）→
  そのファイルだけコミットから外して残りを完走し、該当箇所を提示してどう直すか（環境変数化など）を確認する。
  勝手に値を書き換えない。

### 自律判断の範囲

- 分割粒度・コミットメッセージ・ステージング順はすべて自分で決める。確認は取らない。
- 引数で「まとめて」と明示されたとき（例: 「1コミットで」）だけ分割せず1コミットにする。
- **submodule は対象外**: 中身の未コミット変更（status の `m`）はスキップして報告のみ。
  gitlink 更新（`M <submodule>`）は、submodule 側が push 済みで意図が明確な場合のみ含める。
- ファイルの移動・リネーム・削除など差分に無い操作は勝手にしない（コミットはあるがままの配置で行う）。

コミットメッセージは引数で渡された場合はそれを使用し、無ければ差分から各コミットに合わせて生成する
（リポジトリの既存コミットの文体に合わせる）。

引数: `$ARGUMENTS`
